# Security Drill

**社内セキュリティ訓練**

疑わしいメールを送って、引っかかった人から学ぶ

---

# 課題

フィッシングは「知っている」だけでは防げない。

e-learning や資料配布だけでは、実際にリンクを踏むリスクは減らしづらい。

訓練が形骸化しがち、という問題がある。

---

# 解決の切り口

**疑わしいメール（模擬）を、実際に送る。**

- クリックした人 ＝ 引っかかった人
- その人だけに、その場で学習・クイズを提供
- 合格するまで繰り返し → スコアで可視化

「実践型」の訓練で、気づきと定着を促す。

---

# 管理者の流れ

訓練の作成から配信まで、一つの画面で完結。

- シナリオ選択（パスワード再設定・請求・配送など）
- **AI でメール文面を生成**（件名・本文・誘導文）
- クイズも AI で一括生成 → 編集・保存
- 対象者・チャネル（メール / Slack）を選んで配信

---

# 利用者の流れ

届いたメールのリンクをクリックすると ——

- クリックが記録され、学習ページへ誘導
- 危険性の説明を読む
- セキュリティクイズに合格するまで受験
- 完了画面でポイントを確認

引っかかった人だけが「学ぶ」設計。

---

# 差別化・技術

**既存の e-learning との違い**

- 「資料を読む」ではなく、**実際に疑わしいメールを送り、引っかかった人だけにその場で学習**させる実践型
- クリック・合格状況を可視化し、組織のリテラシーを測れる

**技術のポイント**

- **ローカル LLM（Ollama）** — 訓練文面・クイズ生成は社内完結。データを外に出さない
- **安心設計** — オプトイン/オプトアウト、監査ログ、プロンプトインジェクション対策
- Next.js フルスタック・feature 単位のクリーンアーキで、拡張・運用を想定した構成

---

# 今後やりたいこと

- **シナリオ管理** — シナリオの CRUD とプロンプトテンプレート管理（月1回程度の更新を見据えて）
- **ランダム配信** — BullMQ + Redis で不定期送信ジョブ化、対象者・シナリオのランダム選定
- **ジョブ運用** — 配信の scheduled/processing/done/failed とリトライ・冪等性
- **Slack 強化** — Slack Web API による ID 正当性チェック、Slack App（Bot）での柔軟な配信
- **クイズ拡張** — 記述式（text）出題対応、問題数 10〜15 問への拡張

---

# まとめ

Security Drill は、「送る → 引っかかる → 学ぶ」を実現する社内セキュリティ訓練です。

ローカルLLMと安心設計、拡張設計で、そのまま実運用を想定した構成にしている。
