# セキュリティクイズ仕様

本ドキュメントでは、Security Drillアプリケーションのセキュリティクイズの仕様、データ構造、採点ロジックを定義する。

---

## 概要

セキュリティクイズは、訓練メール内のリンクをクリック→学習説明ページを閲覧した後に、ユーザーが知識定着を確認するための問題集である。

- **目的**：訓練内容の理解度確認
- **出題方式**：訓練シナリオごとに LLM が自動生成
- **出題数**：3〜5問（※ローカルLLM利用時のタイムアウトを避けるため少ない問題数としていますが、将来的に外部API等に移行した際は10〜15問への拡張を想定しています）
- **合格点**：80点以上

---

## LLM による受験フィードバック分析

### 目的

受験者が複数回クイズに挑戦する際に、LLM がこれまでの受験履歴を分析して：
- ✅ できているところ（強み）
- ❌ 弱いところ（改善ポイント）
- 💡 次に学習すべき内容（アドバイス）

を具体的にフィードバック。受験者の学習効果を高める。

### フィードバック生成タイミング

1. **不合格時（再受験前）**
   - 今までの受験パターンから「弱点」を指摘
   - 「次はここに注意してください」というピンポイントなアドバイス

2. **合格時**
   - 全受験履歴の総合分析
   - 「最初は △△ が弱かったが、最終的に克服できた」というプロセス評価
   - 今後の学習へのアドバイス

### 受験履歴の保持

すべての受験回数・回答・スコアを保持し、LLM 分析に利用。

**データ構造例：**

```json
{
  "drillId": "drill-123",
  "userId": "user-456",
  "attempts": [
    {
      "attemptId": "attempt-1",
      "attemptNumber": 1,
      "score": 60,
      "passed": false,
      "submittedAt": "2026-02-27T10:00:00Z",
      "answers": [
        { "questionId": "q1", "selectedOptions": ["opt2"], "isCorrect": false },
        { "questionId": "q2", "selectedOptions": ["opt1", "opt3"], "isCorrect": true }
      ]
    },
    {
      "attemptId": "attempt-2",
      "attemptNumber": 2,
      "score": 85,
      "passed": true,
      "submittedAt": "2026-02-27T10:30:00Z",
      "answers": [
        { "questionId": "q1", "selectedOptions": ["opt2"], "isCorrect": true },
        { "questionId": "q2", "selectedOptions": ["opt1", "opt3"], "isCorrect": true }
      ]
    }
  ]
}
```

### LLM フィードバック生成

**入力データ**
- 受験履歴（すべての attempt）
- 各問題の内容・正解
- クイズの学習テーマ

**出力形式**

```json
{
  "analysis": {
    "strengths": [
      "フィッシングメールの特徴認識は最初から正答できており、セキュリティ意識が高い",
      "複数回の受験を通じて、段階的に正答率が向上している（60% → 85%）"
    ],
    "improvements": [
      "多要素認証（MFA）の重要性についての理解が弱かった（1回目は誤答）",
      "メール送信者確認手法の詳細について、もう一度確認が必要"
    ],
    "advice": [
      "今後のセキュリティ訓練では、MFA に関する実践的な演習に参加することをお勧めします",
      "メールセキュリティに関して、会社の IT サポートが提供する追加資料を参照してください"
    ],
    "overallFeedback": "セキュリティ意識が高く、フィッシング詐欺への対策知識は十分です。今後は、システムレベルの対策（MFA等）についても理解を深めることで、より強固なセキュリティポスチャが実現できます。"
  }
}
```

## MVP 実装詳細

### LLM フィードバック分析の実装

**フロー：**

1. ユーザーが答を送信 → `QuizAttempt` レコード作成
2. スコア計算 → 合格判定
3. **不合格の場合**：
   - 現在までの受験履歴をDB から取得
   - LLM に「弱点分析」を依頼 → フィードバック生成
   - クイズ画面に「次はここに気をつけてください」と表示
   - ユーザーは再受験可能
4. **合格の場合**：
   - 全受験履歴を DB から取得
   - LLM に「総合分析」を依頼 → フィードバック生成
   - `/learn/[drillId]/complete` へリダイレクト
   - 完了画面にフィードバック（strengths / improvements / advice）を表示

**キャッシング：**
- 同じ受験履歴に対する LLM 分析は キャッシュ（`feedbackCache` テーブルなど）
- 新規受験 → キャッシュ無効化

**プロンプト生成：**
- `features/learning/feedbackAnalysis.ts` で受験履歴 → LLM プロンプトに変換
- LLM レスポンス → JSON パース → フロントで表示

## MVP 仕様（Phase 1）

### 対応問題形式

**radio（単一選択）**
- 1つの正解を持つ問題
- ユーザーはラジオボタンで1つ選択
- 得点：正解で得点、不正解で 0点

**checkbox（複数選択）**
- 複数の正解を持つ問題
- ユーザーはチェックボックスで複数選択
- 得点：正解数と選択数に基づいて部分点対応（後述）

**text（テキスト入力）**
- MVP では未対応（将来実装予定）。DBとAPIスキーマは先行対応済み。

### フィールド説明

| フィールド | 型 | 説明 |
|-----------|-----|------|
| `id` | string | 問題の一意識別子 |
| `question` | string | 問題文 |
| `description` | string | 補足説明・概要（表示は任意） |
| `type` | string | 問題形式: `radio` / `checkbox` / `text`（future） |
| `options` | array | 選択肢リスト |
| `options[].id` | string | 選択肢の一意識別子 |
| `options[].label` | string | 選択肢テキスト |
| `correctAnswers` | array | 正解の選択肢 ID リスト |
| `explanation` | string | 解説テキスト（正答後に表示） |

## 採点ロジック

### MVP：radio / checkbox のみ

**radio（単一選択）：**
```
if ユーザー選択 === 正解:
  得点 = 100 / 問題数
else:
  得点 = 0
```

**checkbox（複数選択）：**
```
正解数 = ユーザー選択 ∩ 正解の数
選択数 = ユーザーの選択数

if 選択数 == 0:
  得点 = 0
elif 正解数 == 選択数 == 正解の数:
  得点 = 100 / 問題数  （完全正解）
else if 正解数 > 0:
  得点 = (正解数 / 正解の数) × (100 / 問題数)  （部分点）
else:
  得点 = 0
```

**例：5問中 1問が checkbox で正解3個、ユーザーが2個選択して1個正解**
```
得点 = (1 / 3) × (100 / 5) = 6.67点
```

### 合格判定

```
合計得点 >= 80点 → 合格
合計得点 < 80点 → 不合格（再受験可）
```

## LLM による生成

### 生成プロセス

訓練作成時（`/admin/drills/create`）において、生成は「メール本文」と「クイズ」の2つに分離して行われる。

**1. メール本文生成**
   - シナリオを選択し「AIに生成させる」を実行すると、メール件名・本文・誘導テキスト等が生成される。

**2. クイズの問題群生成（チャンキング処理）**
   - メール本文が確定した後、「生成された本文を元にAIでクイズを自動生成する」を実行する。
   - **直列生成（Sequential Chunking）**: 
     - ローカルLLMのリソース枯渇・タイムアウト・JSONパースエラーを防ぐため、複数問を生成する際は「1問だけ出力する」APIをサーバ側で指定回数（デフォルト3回）直列（順次）ループさせてクイズを構築する。
   - **画面からの生成操作**:
     - **新規一括生成**: 既存問題を初期化し、3問を一括で新規に生成する。
     - **1問追加生成（AIで1問追加）**: 編集画面（admin/drills/[id]）にて、現在すでにある問題との重複を避けるよう既存問題リストを文脈としてLLMへ渡し、新しい問題を1問だけ生成して末尾へ追加する。
   - 生成内容:
     - 各問題文（メール内容とシナリオに沿った内容）
     - 各選択肢（正解1つ、近い誤答2〜3つ）
     - 各解説（正答後に表示する理由）

## 将来実装（Phase 2）

### text（テキスト入力）対応

**使用シーン**
- 「この状況での最適な対応は何ですか？」というような記述式問題
- セキュリティプロトコルのコマンド入力
- リスク判定の理由説明

**ハイブリッド採点ロジック**

```
Step 1: キーワード抽出
  - LLM が期待回答からキーワード3〜5個を抽出・生成
  - キーワード例：["フィッシング", "認証情報", "メール送信者確認"]

Step 2: キーワード照合
  - ユーザー回答がすべてのキーワードを含むか確認
  - 含む → Step 4 へ（合格）
  - 含まない → Step 3 へ

Step 3: LLM による詳細判定
  - ユーザー回答と期待回答を LLM に投げて意味判定
  - 「同じ意味だが別の表現」も正解として扱う
  - 部分点も対応

Step 4: スコア決定
  - 完全正解: 100 / 問題数
  - 部分正解: (部分度合い) × (100 / 問題数)
```

**データ構造（将来）**

```json
{
  "id": "q3",
  "question": "フィッシングメールだと気づいた場合、どのような対応をすべきですか？",
  "type": "text",
  "expectedAnswer": "フィッシングメールであることを確認したら、メールを削除して、会社の IT サポートに報告する。認証情報は絶対に入力しない。",
  "keywords": ["フィッシング", "認証情報", "入力しない", "報告", "削除"],
  "explanation": "...",
  "validationMethod": "hybrid"  // keyword → llm
}
```

## 実装上の注意点

### MVP 実装

1. **LLM 生成結果の確認**
   - 管理者が「配信可能にする」時点で、生成されたクイズの妥当性を確認
   - 手動編集で選択肢や問題文を修正可能

2. **バリデーション**
   - 必須項目：問題文、選択肢（複数）、正解、解説
   - 選択肢は最低2個以上必須（radio）、3個以上推奨（checkbox）
   - 正解は必ず1つ以上選択必須

3. **レイアウト**
   - 問題を順番に表示
   - 前後の問題へのナビゲーション機能
   - 進捗表示（○問中△問完了）

### 将来実装時

1. **キーワード管理**
   - LLM が生成したキーワードを管理者が確認・調整可能

2. **LLM コスト管理**
   - 受験者ごとに採点 LLM を実行
   - ローカル LLM のため、コスト制約なし

3. **採点キャッシング**
   - 同じユーザーの再受験時は、前回採点結果を参考に効率化
