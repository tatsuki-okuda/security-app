# 訓練（Drill）ステータス遷移フロー

本ドキュメントでは、Security Drillアプリケーションの訓練（Drill）のステータス遷移とその詳細を定義する。

詳細な画面構成は [../screenConfiguration.md](../screenConfiguration.md) を参照。

---

## ステータス定義

訓練には以下の4つのステータスがある：

### 1. **下書き（Draft）**

- **説明**：新規訓練作成時の初期状態
- **使用場面**：
  - 訓練作成途中で保存
  - 途中まで入力した状態を一時保存
- **可能な操作**：
  - 保存（バリデーションなし）
  - メール内容編集
  - クイズ内容編集
  - AI再生成
  - 「配信可能にする」ボタン押下 → 必須項目をチェック
- **入力完了度**：任意（不完全でも保存可能）

### 2. **配信可能（Deliverable）**

- **説明**：訓練内容が完成し、いつでも配信できる状態
- **使用場面**：
  - 全ての必須項目が入力されている
  - バリデーション完了
  - 配信待機中
- **可能な操作**：
  - 保存（内容編集後）
  - メール内容編集
  - クイズ内容編集
  - AI再生成
  - 「配信する」ボタン押下 → 配信モーダルで対象者・チャネル選択
- **入力完了度**：100%（必須項目全て入力）

### 3. **配信中（Delivering）**

- **説明**：訓練が対象者に配信されており、現在実施中の状態
- **使用場面**：
  - 訓練メールが送信され、対象ユーザーが学習・クイズに取り組んでいる
  - ログ・結果が記録されている
- **可能な操作**：
  - 訓練内容の編集（配信中でも修正可能）
  - ログ・結果確認
  - 「配信停止」ボタン押下
  - 将来：同じ訓練を追加配信（不定期配信機能）
- **入力完了度**：100%

### 4. **配信停止（Stopped）**

- **説明**：訓練実施が終了した状態
- **使用場面**：
  - 訓練期間が終了
  - 管理者による停止指示
  - アーカイブ済み
- **可能な操作**：
  - ログ・結果確認（読み取り専用）
  - 監査・レポート参照
- **入力完了度**：100%

## ステータス遷移フロー

![Drill Status Flow](./assets/drill-status-flow.png)

### 遷移の詳細

#### **Draft → Deliverable**

**トリガー**：「配信可能にする」ボタン押下

**バリデーション**：以下の必須項目をチェック

**メール必須項目：**
- 件名（Subject）：入力必須、空でない
- 本文（Body）：入力必須、空でない
- 誘導テキスト（Guidance Text）：入力必須、空でない

**クイズ必須項目：**
- 問題文（Questions）：入力必須、空でない
- 選択肢（Multiple Choices）：複数（最低2個以上）必須、各選択肢が空でない
- 正解（Correct Answer）：選択肢から1つ選択必須
- 解説（Explanation）：入力必須、空でない

**バリデーション結果**：
- ✅ **成功**（全て入力）：Draft → **Deliverable** へ遷移
- ❌ **失敗**（不足あり）：Draft のまま、エラーメッセージ表示
  - エラーメッセージ内に不足項目を明記
  - ユーザーは入力フォームで該当箇所を修正可能

#### **Deliverable → Delivering**

**トリガー**：「配信する」ボタン押下

**配信モーダル表示**：
- 対象者選択（全員 / ランダム / 個別）
- チャネル選択（メール / Slack / 両方）
- 送信タイミング（即時 / 指定時刻）

**配信実行**：
- `Interaction` レコード作成（配信ログ）
- `trackingToken` 発行
- メール/Slack送信
- Deliverable → **Delivering** へ遷移

#### **Deliverable → Deliverable（編集）**

**トリガー**：「編集」ボタン押下 or 直接フォーム編集

**編集後の保存**：
- 保存時のバリデーション：不実行（任意の状態で保存可能）
- ステータス：Deliverable のまま

#### **Delivering → Stopped**

**トリガー**：「配信停止」ボタン押下

**停止処理**：
- 配信を停止（新規送信なし）
- 配信ログは保持
- ユーザーが既に受け取ったリンクは有効なまま
- Delivering → **Stopped** へ遷移

## 各画面でのステータス表示

### `/admin/drills` （訓練一覧）

- 全訓練をステータス別に表示
- フィルタリング機能：Draft / Deliverable / Delivering / Stopped で絞り込み可能
- 一覧表示：訓練名、ステータス、送信日時、対象者数など

### `/admin/drills/create` （訓練作成）

- 新規作成開始時：自動的に Draft ステータスで作成
- 初回保存時：Draft
- 「配信可能にする」ボタンで Deliverable への遷移試行
- 成功時：確認ページ表示
- 失敗時：エラーメッセージ + 編集フォーム表示で継続編集

### `/admin/drills/[id]` （訓練詳細）

- 現在のステータスをプロミネント表示
- ステータス別の可能アクション表示：
  - Draft：「配信可能にする」ボタン
  - Deliverable：「配信する」ボタン + 「編集」ボタン
  - Delivering：「配信停止」ボタン + 「編集」ボタン + ログ表示
  - Stopped：ログ表示のみ（読み取り専用）
- 訓練内容、使用プロンプト、ログ、結果表示

### `/admin/drills/[id]/edit` （訓練編集）

- 現在のステータスを表示
- Deliverable / Delivering の状態で編集可能
- 保存後もステータス維持
- 「配信する」ボタン：Deliverable の場合のみ表示

## 実装上の注意点

1. **バリデーション**
   - 保存時（Draft状態）：バリデーションなし
   - 「配信可能にする」押下時：全バリデーション実行

2. **ステータス遷移の冪等性**
   - 同じボタンを複数回押しても同じ結果を得られるように実装
   - DB トランザクション管理

3. **ユーザーへの UX**
   - ボタンの有効/無効を明確に
   - エラーメッセージは具体的に（どの項目が不足しているか）
   - ステータスバーまたはバッジで現在のステータスを常に表示

4. **将来構想**
   - 不定期配信機能：Delivering 中に追加配信可能
   - スケジュール配信：指定時刻での自動遷移
   - ステータス通知：ステータス変更時にメール通知
