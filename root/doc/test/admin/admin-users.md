# Admin2-1/2 `/admin/users` & `/admin/users/[id]` テスト設計

## スコープ・参照

- 画面: 参加者一覧・参加者詳細
- 仕様: `doc/screenConfiguration.md` Admin2-1, Admin2-2
- 参照: `doc/architecture.md`, `doc/drills/drillStatusFlow.md`, `root/plan/override.md`

## 前提

- ロール: Admin のみ。未ログインはログインへ、Admin 以外は 403 相当。
- データ: 複数ユーザー、オプトアウト状態のユーザー、訓練履歴付きユーザーを用意。

## テストレベル別観点

- usecase: 一覧取得に Drill/Interaction/QuizAttempt を結合。オプトアウト解除操作の扱い。
- infrastructure: クエリの結合と N+1 回避、存在しないユーザー ID の例外変換。
- Server Action/Server Component: ロールチェック、存在しない ID で 404/エラー表示。Role 更新時のバリデーション（マスター管理者の更新ブロック含む）。
- UI: テーブル表示、ステータスラベル、詳細リンクの遷移、オプトアウト解除ボタンの活性条件。Role 変更セレクトボックス（マスター管理者以外は変更可能、マスター管理者は disabled）。
- E2E:
  - 一覧: メール、最新訓練ステータス、オプトアウト状態が表示される。
  - 詳細: 訓練履歴（送信日時・クリック・学習・クイズ結果）が表示される。
  - オプトアウト解除操作が成功/失敗を適切に表示する。
  - Role（権限）の変更操作が反映されること。また、環境変数 `AUTH_ADMIN_EMAILS` で指定されたマスター管理者の権限は変更不可（UI が disabled）であること。

## ケース一覧（抜粋）

- P0 正常: 一覧に登録済みユーザーが表示される。
- P0 正常: 詳細で対象ユーザーの訓練履歴が表示される。
- P1 エラー: 存在しない ID へアクセスすると 404/エラー表示。
- P1 権限: Admin 以外がアクセス → 403 相当。
- P1 操作: オプトアウト解除成功で状態が更新される。
- P1 操作: 一般ユーザーの Role を `admin` に変更でき、反映される。
- P1 権限: マスター管理者（`AUTH_ADMIN_EMAILS`）の Role は変更できず、UI も無効化されていること。
- P2 性能: 一覧取得が想定件数でタイムアウトしない（大規模データ想定）。
